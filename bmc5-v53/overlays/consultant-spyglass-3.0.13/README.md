# Consultant spyglass and jukebox crash fix candidate

`/konsultant-item presets` and tab completion omitted `spyglass`. Giving an ordinary spyglass instead also failed for a Konsultant because the role's generic right-click restriction canceled use. This overlay adds a tagged vanilla spyglass preset, keeps the existing expiry and protected-equipment behavior, and lets that specific item zoom when used in air or while pointing at a block. An untagged spyglass does not gain the exception.

Two real client crash reports from 9 October identify a separate regression when music plays. The 3.0.11 music fix moved `MusicAudibility` out of the mixin-owned package, but `ScooterAudioClient.hasAudibleMusic` retained one call to its old location. Mixin then refuses to load the old helper and disconnects the client. `PatchMusicReference.java` changes that one call to the existing relocated helper, with the exact method signature checked. The build scans every class for surviving references to the old package.

`build.py` requires the exact verified live 3.0.12 JAR (SHA-256 `6fbde292e6e88a0fa250966203c173ca06ebf77b36d1530eab4de82763f12566`) and the existing Java 21 SDK classpath file. It changes exactly `CustomPresets.class`, `PsychiatrykRoles.class`, `ScooterAudioClient.class`, and the six metadata versions to `3.0.13-bmc5`. It refuses a different input, missing dependencies, unexpected class outputs, duplicate/corrupt ZIP entries, or any extra JAR change. The original 3.0.12 installer and live server are untouched by this build.

The isolated test mod `SpyglassCheck.java` checks the command preset list, the resulting vanilla item and consultant tag, timed expiry, untagged-item exclusion, and NeoForge air/block interaction events. `supervise_spyglass.py` starts a separate loopback-only full-pack dedicated server on the user's CachyOS QA machine with a 3 GiB heap, 6.5 GB address-space limit, available-memory guard, 600-second deadline, and clean stop. The helper JAR is test-only and must not be included in a public installer or production server.

The combined candidate JAR is SHA-256 `9d8c6b62c17d4c20b67ea3d208c5adef0a150a899433fb5fe825c0b63e439bed`. ASM verification passed for all three changed classes. In the isolated 299-JAR full-pack server, the initial test-helper package collided with the Roles module; moving that helper into its own package resolved the fixture error. The first functional run then exposed that the live 3.0.12 Roles class never connected `CustomPresets` to the command. The corrected patch adds only `spyglass` to the command list and routes only that preset to the helper. The combined build's full-pack run reached `Done`, printed `SPYGLASS_CHECK PASS list + vanilla item + consultant tag + expiry + air/block use`, and saved all dimensions on a clean exit. The status is in the ignored `build/remote-status.json` and the source test is `SpyglassCheck.java`.

The candidate has now passed an isolated, real-client jukebox playback and spyglass zoom check against a matching QA server; see `QA_RESULT.md` and the two screenshots in `evidence/`. It is **not deployed**. The change modifies native client interaction code, so the current 3.0.12 client cannot be assumed compatible with a server-only rollout. Production distribution must update both the server JAR and the AutoModpack copy, with readback hashes and a clean restart.
