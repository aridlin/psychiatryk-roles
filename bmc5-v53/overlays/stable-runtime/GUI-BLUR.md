# Psychiatryk GUI world blur

NeoForge 21.1.252 `Screen.renderBackground` always calls `renderBlurredBackground`, including on in-world addon screens. Several addon `render` methods call `renderBackground` and then `super.render`, causing that blur path twice in one frame. The new client-only `ScreenBlurMixin` cancels only that blur call for the exact 10 existing addon screens plus the new `RuntimeScreen`, and only while a world is loaded. `renderMenuBackground` and each screen's drawing code still run, preserving its shading, text and art. Vanilla, third-party, title-screen and unknown screens retain default behavior.

The targeted list includes `ScooterMusicScreen` (the wearable jukebox reuses it), `ScooterDismantlerClient$1` (the scooter workstation prompt), `PokerScreen`, `PeebSettingsScreen` and `RuntimeScreen`. `PsychiatrykCreative` registers a creative tab and is not itself a Screen. No owned class literally named “creative prompt” was found in the exact queued 3.0.9 jar, so vanilla creative inventory and generic confirmation screens are deliberately outside the fix.

Integration is already in `psychiatryk-runtime.mixins.json` under the `client` key. Build it with the normal stable-runtime builder after the unrelated `AssetClient` source edits compile. Do not add the mixin to the common `mixins` array; dedicated servers must never load Minecraft client classes.

Checks: `GuiBlurPolicyTest` passed 13 positive/negative checks with a 64 MB runtime heap. The mixin and policy compiled against the exact queued 3.0.9 jar and NeoForge development classpath with a 192 MB compiler heap. All ten pre-existing allowlisted classes were confirmed present in the queued jar; the eleventh is `RuntimeScreen` in this overlay. NeoForge's actual `Screen` bytecode has the targeted `renderBlurredBackground(float)` method. A full candidate build was attempted in isolated `/tmp/psychiatryk-gui-blur-build` and failed on six concurrent, unrelated `AssetClient.java` symbol errors, not on this change. In-game visual verification is still required before calling the blur behavior proven.
